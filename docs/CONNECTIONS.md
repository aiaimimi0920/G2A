# 本地发现与连接授权草案

本文补充 G2A 的接入流程，不增加中心账号依赖。`PairingCoordinator` 是可信本地 UI 的参考协调器，不是公共网络 API，也不是唯一允许的发现方式。实际传输仍使用规范的描述、邀请与会话接口。

## 两条加入路径

### 桌面伙伴已运行

1. 可信本地启动器注册它实际拥有的游戏宿主及回环 endpoint。
2. 桌面伙伴读取游戏描述，向玩家展示游戏、伙伴、玩家身份、行动权限和呈现条件。
3. 玩家允许才创建短期邀请并发起 HTTP join。拒绝、请求到期或条件变化均不得加入。
4. 玩家明确选择自动加入时，可以记住精确授权范围。同一范围下的下次请求无需再询问；新权限、游戏描述/能力版本、伙伴、玩家或宿主实例改变，必须重新询问。

### 游戏内“链接我的伙伴”

1. 玩家选择伙伴。没有运行的伙伴时，生成待批准请求，而非静默启动应用。
2. 玩家批准后启动本地伙伴，再发起连接；此前保存的自动加入许可不等于自动启动新应用许可。
3. 当前示例启动的是实际 Tk 伙伴窗口，不是独立供应商应用或 OS 自定义 URI handler。云端提供者选择、浏览器授权和 OS 唤起仍未实现。

## 安全边界

- 发现信息、请求 ID 和游戏自述不是授权凭据。
- `register_game`、`approve`、`deny`、自动加入设置只可由可信宿主/用户界面调用，不能暴露给 Agent 或任意网页。公开部署这些方法会破坏信任边界。
- 参考协调器按 UI 事件循环单线程调用；不是线程安全的共享认证服务。未来独立进程绑定需定义双方身份、调用授权、重放保护和生命周期。
- 邀请只在批准后创建，绑定玩家、伙伴和游戏允许的行动集合。用户不能请求游戏没有开放的行动。
- 批准固定游戏描述与能力版本；邀请也绑定该状态，避免在邀请创建与 join 之间替换呈现/权限条件。
- 连接请求保留 60 秒，最多 64 个；游戏注册最多 32 个。自动许可仅存在本进程内，尚不持久化。撤销许可阻止尚未连接的自动加入，已连接会话通过明确退出结束。
- 参考实现没有网络端口扫描、广播、全局目录或任意 URL handler 执行。注册信息来自可信启动器，不应伪称完成了跨厂商安全发现。
- 伙伴窗口的加入前状态在连接时采样，不使用较早弹出询问时的过时状态。

## 参考状态流程

`awaiting_approval` → `authorized` → `connecting` → `connected`

拒绝进入 `denied`，连接失败进入 `failed`。过期请求返回 `request_expired`，授权条件变化返回 `approval_stale`，未经批准连接返回 `consent_required`。改变返回的 offer 副本不能改变内部授权状态；请求 ID 不是给不受信任调用者操作批准接口的能力凭据。

本阶段这些状态是协调器 API 约定，不是另一个已经标准化的远端绑定。远端发现与授权需单独设计、验证和版本化，不能直接通过网络序列化一个 Python 对象就宣称可用。

## 实际窗口示例

安装 Python 包后，在仓库根目录运行：

```sh
python examples/local_pairing.py
```

需要支持 Tk 的 Python 和可用桌面显示。两个入口连接同一真实回环 HTTP 宿主；桌面伙伴窗口按 `hide_desktop` 隐藏，正常退出或租约失效后恢复加入前状态。原来隐藏的窗口退出后仍隐藏。此示例不执行 Godot 游戏动作，Godot 行动示例另见 `examples/godot_key_quest/`。

测试：设置 `G2A_GUI_TEST=1`，执行 `python -m unittest discover -s tests -p 'test_pairing*.py' -v`。GUI 测试调用实际 Tk 按钮回调并检查窗口状态，不是人工鼠标点击测试，也不证明 MotGUI 集成或 OS 应用崩溃恢复。未设置显示测试变量时，窗口用例明确跳过。

跨进程桌面恢复、持久化自动加入偏好、陌生游戏身份认证、应用唤起、云端选择/授权均继续开放。不能用这个可信同进程协调器替代完整 R10-R12 验收。
