# G2A 下一版协议设计与伪代码

状态：`g2a-design-1` 工作草案；2026-10-07。目标是完整定义协议，并以伪代码和场景推演贯通流程，不要求当前阶段可编译或生产运行。

该设计线与 [0.1.0-dev 实验规范](../SPECIFICATION.md) 分开。`g2a-design-1` 是文档修订标识，不是可向旧实现发送的 wire 版本。旧 schema、SDK 和示例不因本文自动升级。新的方案选择是在当前目标授权下提出的设计默认值，不代表对外稳定兼容、账户授权、付费、公开发布或许可变更。

## 当前工作规则

- 不再以扩展 Godot、Tk、MotGUI 或部署云服务作为主线。
- 不依赖 GitHub Actions，不通过修改账单解决协议问题。
- 伪代码中的外部适配器必须有输入、输出、错误和安全保证，不能只留下含义不明的 `TODO`。
- 架构可以抽象真实网络、加密、数据库和引擎，但不能抽象掉授权决定、状态转换或副作用时点。
- 保留现有代码和本地证据；新的设计未迁移前，不声称现有 SDK 已符合该设计。

## 设计与发布的区别

完整设计应覆盖本地/云端、两个接入入口、主动交互、权限、受众、记忆来源、形象呈现、异常恢复、多连接和兼容演进。稳定发布还需要真实独立实现、性能/安全验证和权利人发布决定；后者不得伪装为本轮已经发生。许可/名称未知事项使用明确发布门禁，不阻碍协议语义研究，也不自动替用户作法律决定。
