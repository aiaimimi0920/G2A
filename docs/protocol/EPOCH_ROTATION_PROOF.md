# 长期身份代次切换：独立参考模型

后续已补 [旧快照与混合账本恢复校验](EPOCH_RECOVERY_PROOF.md)，仍为独立内存模型，
不替代真实持久存储和 wire 接入。

## 目标与实现范围

`epoch_rotation.py` 是独立可执行设计模型，不是 RelayHarness 的新入口，也不修改
现有 mailbox wire schema 或其最多 8 个身份的限制。它验证下一阶段解除该限制所需
的顺序约束，不能把模型通过表述成现有 Relay 已支持长期轮换。

身份采用 `(epoch, local_id)`；epoch 是 authority 持久保存的单调整数，local_id
只能在新 epoch 下复用。游戏端口保留当前 epoch 作为旧身份的统一拒绝规则，因此
无需永久保存每个旧 mailbox 的墓碑。初始 epoch 为零，不允许跳代或整数回绕。

## 三个独立提交点

1. **Relay 封存**：所有邮箱已关闭后封存当前 epoch，停止注册和新 claim 领取。
   封存不取消已领取/正在执行的请求，不删除记录。
2. **游戏切换**：确认 Relay 的可信封存见证，且所有已开始调用均已收敛后，游戏
   端口提交 epoch+1 与旧 journal 清空。任何旧 claim 在查询 journal 前即拒绝。
3. **Relay 切换**：确认游戏已提交完全相同的目标 epoch，才清理旧邮箱/配对消费
   记录并开放新 epoch 注册。两者之间的间隙只允许拒绝新准入，不能先开放再追赶。

每一步都有独立提交前/后故障；不跨 authority 回滚。提交后丢响应按同一目标 epoch
重试，读到相同目标即收敛。不可拿更旧目标复用当前代次，不可因超时跳到更大代次。
封存和切换握手是可信内部事实，不能接受外部请求自报“已全部关闭”或“游戏已切换”。

## 旧身份、未知效果与期限

配对同意证据必须绑定 epoch。清理旧消费标记后，旧 epoch 的证据仍因代次不匹配
被拒绝；新代次中的同名 proof 只能由新的可信批准产生。旧 token、claim、原注册
回执不能被客户端改写 epoch 后重用，生产适配器必须做不可伪造的完整绑定。

已进入游戏端口的调用阻止切换。重启保留 unresolved inflight，既不自动重执行，
也不把未知动作当作未执行来清空。模型 finish 是可信完成事件，不是推测成功；若
实际效果无法查证，本方案牺牲可用性并保持阻塞，不提供强制忘记后继续的捷径。

仅等待固定 TTL 不足以授权删除；需要旧代次拒绝规则已经持久提交。原业务结果与
结果读权不随 identity 轮换自动删除，未决动作也不能换新业务 ID 自动重发。

## 证据

八个测试覆盖：局部编号复用但完整身份不同、活动邮箱与在途调用阻止切换、迟到 claim
在游戏切换前后两种交错、跨 authority 间隙拒绝准入、三个提交点的前后故障及假重启、
20 次代次轮换/160 个旧 claim 拒绝、未决调用重启不自动收敛、严格整数/禁止跳代与回绕。
测试仅探索有限状态，不构成数学证明或真实持久存储认证。

## 接入前必须完成的合同

- 将 epoch 绑定到 mailbox 身份、配对证据、外层凭据、claim 和回执查询目标，并明确
  旧版本无 epoch 时拒绝而不是默认补成当前值。
- 将封存/游戏切换见证绑定固定 authority、目标 epoch 与持久实例身份，定义认证和重放拒绝。
- 定义旧控制回执保留期限与查询终态；模型只验证执行拒绝，未实现旧回执归档查询。
- 定义双 authority 独立持久恢复、在途效果查证及运维恢复流程，防止旧快照回滚 epoch。
- 保留现有 wire 兼容性与权限边界，通过组合 Harness 和跨语言互通后才替换 8 邮箱限制。
