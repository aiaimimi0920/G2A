逐操作审查实际促成以下修订，而不只是给既有结果贴完成标签：

5. 隐私存储处理增加 pending 回执，不要求外部未完成操作伪造 done。
6. 资源缓存回执同时绑定 parser 与 policy revision。
7. 统一错误映射区分提交前、提交后与未知，不从异常文本猜回滚。

## 5. 后续反例复核：不能从绿色测试推出完整性

对 relations.py 的反向审查先增加回归测试并实际运行，得到 4 个失败，再修复：

| 反例 | 原缺口 | 修订 |
| --- | --- | --- |
| Scope 起始时间晚于 now，Grant 为 active 且摘要正确 | 活动写入检查仅检上界 | Grant 有效区间检查包括 created_at 下界 |
| 已认证但非批准聊天成员、第三者私聊或发送者已退出 | 只检查发送者身份相等与接收者集合 | 聊天发送者也检查当前成员、批准范围和频道资格 |
| chat.message 携带空 payload | 通用 Envelope 不约束聊天字段 | 关系边界对聊天额外检查 Chat schema |
| 同一资源子树先从浅路径、后从深路径引用 | 去重提前返回，漏检深路径后代 | 缓存子树高度，所有引用路径验证深度，唯一资源仍只计费一次 |

新增正例保留合法团队发言、非聊天成员的 GameAuthority 情境来源、有效期起始边界、
允许深度下共享依赖不重复计费；深度反例交换兄弟次序后仍拒绝。

这些是本地参考检查器的可复现问题，不是对旧 SDK、真实服务或云端漏洞的推断。
本次不分配新 wire 版本、不部署、不修改 GitHub Actions。

修复后统一入口实际通过：67 个设计测试方法，0 失败/错误/跳过；42 条模型轨迹，0 失败；
生成物一致性检查通过。最新源 hash 和运行记录保存为 linshi 下的
g2a-protocol-design-20261007/adversarial-verification.json；§3 的 62 个是此前证据。

剩余设计验证工作包括：活动请求扩展与协商结果的装配、来源披露记录的权威解析、
