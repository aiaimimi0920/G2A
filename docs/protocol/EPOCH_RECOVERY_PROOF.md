# 代次恢复：拒绝旧快照与混合时点账本

## 为什么 epoch 检查还不够

仅校验快照里的 epoch，无法发现同一 epoch 内丢失了最近一次派发标记。将这样的
旧快照当作完整账本恢复，会把已开始请求当成新请求。两个 authority 的旧/新快照
混合也可能丢失封存或游戏切换事实。因此恢复校验必须覆盖整个模型状态，而非只看 epoch。

## 模型合同

EpochRotation 为每个 owner 保留一个可信状态摘要 checkpoint，并保留实例 ID。
摘要对 dict/set/tuple/list/bytes/null/str/int/bool 做完整类型标记的确定性归一化，再计算 SHA-256。该编码仅用于
本地模型，既不是新增 G2A wire 编码，也不替代已有规范化与摘要合同。

`snapshot()` 返回 instance_id、relay 和 game 的深拷贝，不包含 checkpoint。
`restart(snapshot=...)` 在替换实例前检查：

1. 快照必须恰好包含上述字段，不能夹带自报 checkpoint 覆盖可信恢复依据；
2. 实例 ID 必须一致；不同实例即使内容一样也不能恢复；
3. relay 和 game 必须分别匹配各自最新可信 checkpoint；缺失 checkpoint 一律拒绝；
4. 校验失败不退休当前健康实例，也不修改其账本；校验成功后才退休旧实例。

每个 owner 的状态提交与其 checkpoint 更新视为同一原子提交边界：before_commit
两者均不变，after_commit 两者均已更新。另一 owner 的 checkpoint 不随之提交。
所以 Relay 已封存、游戏已切换而 Relay 尚未开放的中间态可以原样恢复并继续推进，
而从更早时点拿来拼装的账本会被拒绝。

checkpoint 覆盖注册、关闭、派发开始、完成、封存及代次切换。因此同 epoch 内丢失
派发标记的旧快照也无法恢复。未决 inflight 保留，不能自动清除或据此重新执行。

## 关键假设与非目标

本模型的 checkpoints 对象被明确视为**不随候选快照回滚的可信存储**。它与实例 ID
不能从待恢复快照自身重建；散列也不是签名。若攻击者或运维同时回滚快照与可信
checkpoint，本模型无法检测，这一风险没有因使用 SHA-256 而消失。
当前 live state 同样视为可信，不宣称防御进程内任意状态篡改。

真实适配器必须给出等效的持久提交/防回滚保证，例如可证明的最新提交位置与受保护
恢复记录，并处理实际崩溃窗口。当前实现仅用内存锁和故障注入验证合同，不证明磁盘
原子性、不提供可独立部署的备份恢复器、不接入 RelayHarness。

## 验证

新增七个场景覆盖跨 epoch 回滚、同 epoch 派发标记回滚、异实例快照、混合/篡改
账本、提交前后 checkpoint 一致性、缺失/自报 checkpoint 拒绝，以及快照副本隔离
与旧实例禁止导出。上一轮八个切换场景继续通过；组合模型接入和旧回执归档仍未完成。

## 恢复摘要类型碰撞修复

恢复审查实际复现旧归一化的碰撞：`{"a": 1}` 与 `["map", [["a", 1]]]` 产生相同
摘要；tuple/set 的标签也能被普通列表伪装。将 relay 快照替换为其旧归一化列表时，
原恢复函数实际接受 list 状态并退役旧实例。这不是 SHA-256 碰撞，而是摘要输入编码
没有唯一地区分容器类型。

现在所有容器和叶子均按 exact type 标记，保留 claim 所需的嵌套 tuple 和 set 支持；
字典/集合顺序不影响摘要，bool 与 int 不混同，未知类型拒绝。新增三个回归方法验证
真实伪装快照拒绝且原实例仍可恢复、类型区分/无序稳定性，以及不支持值不能退役实例。
此修复也覆盖调用同一摘要函数的 EpochBindingPort 恢复校验。内部摘要格式已变化，
不能以旧算法回退接受历史锚点；本模型没有提供生产快照迁移功能。
