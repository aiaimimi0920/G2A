# 启动成功历史与当前进程存活分离

## 精确进程绑定

首次 session.join 在已有独立启动效果且可信验证为 running 时，将 process_ref 和
完整应用 binding 冻结到 admission_process。后续不是“相同应用又有一个进程”就能
替代原进程；同应用新实例不能完成旧准入或取回旧 join 控制秘密。

现有手工设置 verified running 但没有可查证 process_ref 的旧夹具仍可按原配置
运行；它们明确没有精确监视身份，监视返回 unknown，不虚构进程引用或退出证据。

## 独立退出事实与协调器提交

LauncherPort.record_exit 是可信操作系统观察的模型入口，仅接受精确关联已知启动
效果的 process_ref。它记录不可复活的退出墓碑，只清除同一个当前 running 指针；
迟到的旧进程退出不会清除另一新进程。此入口不是 wire 停止命令，也不终止真实进程。

observe_process 区分 running/exited/unknown：相同绑定且存在当前已验证进程才是
running，精确退出见证才是 exited。进程缺失、绑定不匹配、无记录不等于已退出。
旧 running 快照也不能绕过退出墓碑重新握手或恢复 available。

LaunchHarness.reconcile_application 是可信调度入口，先执行原可信时间维护，再
查独立观察并提交会话状态。只有绑定进程确定 exited 才关闭关联会话；异常、畸形
结果或 unknown 不被当作退出，不清未知、不调用 start。关闭沿用既有事件/动作停止/
呈现释放队列流程，不回滚外部效果。

独立退出先发生、authority 提交前失败时，退出事实仍保留；假重启重试可关闭会话。
提交后丢响应则重复查询，不重复产生关闭事件。启动历史回执仍报告原 started 事实，
不能据此推断进程当前存活，也不能据此自动重启应用。

## 准入与观察失败的区别

已有会话的监视 unknown 保持原会话状态，仍受正常 lease/Grant 门禁约束。尚未 ready
的准入必须证明绑定进程可用；无法证明时不得发布 ready，沿用准入失败的关闭规则，
但这不构成“已证明进程退出”的声明。新进程替换旧进程也不能绕过该门禁。

## 跨语言提交恢复

JS 客户端现通过 20 次新增正式 wire 请求执行两条完整启动/准入/查询链，分别在
监视关闭事务 before_commit 与 after_commit 注入故障，再恢复假账本。独立退出
墓碑必须保留：提交前故障恢复时会话仍 active，提交后故障恢复时已经 closed；
再次协调均收敛为 closed，重复协调不增加事件 sequence。

每条链均验证启动回执仍为 started、operation.get 为 done，旧 join 仅返回
completed_without_secret，不泄露控制凭据；独立 Grant 保持 active，启动调用和
效果始终各一次。退出记录/调度/观察是可信夹具，不是新增公开 wire API，不允许
客户端通过普通请求自报进程已退出。互通门禁要求两个故障窗口、两次关闭和恰好
两次启动的子报告，并拒绝缺失子报告或 bool 冒充整数。正式操作仍为 38 项，
完整互通请求现为 457 次，独立候选 epoch profile 的 26 次另计。

## 证据与剩余范围

### 最大长度许可引用

合法 decision_ref/launch_permission_ref 可达 128 字符。原模型直接拼接
`fixture-process-`，导致生成的 process_ref 超出 Id 上限：启动与加入已成功，
record_exit 却返回 invalid_message，无法记录退出。新增完整准入回归先复现此问题。
现在以完整许可引用的 SHA-256 十六进制摘要加固定前缀生成 80 字符内部引用；
不截断许可 ID，也不改变许可去重键。相同长前缀、末字符不同的两个许可有独立
效果/退出墓碑，旧许可重试不再启动。摘要是内部命名，不是认证或持有权限证明。

重启保留已存 process_ref，不重新推导或改写历史绑定；没有真实旧快照迁移。
历史模型已经生成的超长引用不由本修复自动迁移，不能声称旧持久化数据已修复。

八个新测试方法覆盖确定退出关闭、历史效果保留、无观察/畸形/异常保持 unknown、
两阶段故障和假重启、错误引用拒绝、旧退出不影响新指针、新进程不能完成旧准入、
无引用旧夹具、不健康账本拒绝，以及退出墓碑抵抗旧 running 快照重放。
其中新进程替换反例直接调用可信端口以隔离进程身份问题，不宣称新许可审批链由
该反例验证。无真实 OS 进程、监视守护进程、跨进程持久化或多应用实现。

监视是显式调度，不保证轮询及时性；未知长期收敛、进程身份根/退出证明认证、
多实例应用与退出墓碑回收仍待独立验证，不能把进程消失当作撤权或自动重启授权。
