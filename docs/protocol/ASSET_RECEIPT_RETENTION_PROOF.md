# 资源回执的固定保留期与关闭后回收

## 冻结期限

asset.resolve 首次事务提交同时保存内部 retain_until，值为受理时间加已协商的
Scope.limits.receipt_retention_ms；拒绝超过安全整数范围的相加。成功和已受理失败
均遵循同一规则。重复相同请求不延长期限；内部时间字段不加入公开 AssetReceipt。

在 now < retain_until 时，回执读取仍受既有身份/Scope/Grant 门禁约束。到期时
旧 asset.resolve 回执和 operation.get 查询返回 request_gone，不继续重放原结果。
结果保留不续身份有效期，长保留期末查询必须另有当前有效的原主体身份。

## 清理与不可重执行边界

compact_closed_asset_receipts 是可信有界维护，要求健康账本、关闭会话及到期回执。
默认最多 64 条，允许 1..128 的严格整数；未到期记录不计入待清理数。
清理后 operation.get 无权确认已不存在的记录，返回 permission_denied，不伪造
not_accepted。重新提交旧 asset.resolve 仍被关闭会话的 Grant/状态门禁拒绝，
不会重新下载、解析或发布资源。

本方法不清理缓存或预装目录，也不声称设备已释放。回执只保存查询事实，不是
Renderer 的内容持有证明；下载内容仍必须走独立的 release-before-cache-GC 门禁。
即使多个回执指向相同缓存，清理预算也逐条计数，不借共享内容扩大本次清理量。

## 故障与兼容范围

可信时间维护先独立提交；业务 GC 提交前失败保留记录，提交后丢响应保留清理结果，
假重启后可继续。原公开操作结构不变，但现在明确执行有限回执期限。此内存模型
没有旧磁盘快照迁移协议；未来持久化适配器不得为旧记录随意补一个新的期限来续权，
必须保留原受理时间/冻结政策或按证据不足保守拒绝恢复。

六个新测试方法覆盖成功/失败回执、期限等号边界、不因重试续期、清理后查询知识、
旧请求不可重执行、共享缓存独立保留、逐条预算、提交故障与假重启及活动会话拒绝。
活跃会话的长期回执回收、跨会话索引和生产存储仍未证明。
