# G2A 对外发布路线

本文是发布计划，不表示网站、公共包或稳定版本已经上线。G2A 是独立的 Game-to-Agent 协议，Mot 是实现者之一；使用规范不能以 Mot 账号、模型或收费中心服务为前提。

## A2A 提供的不是一个中心 API

2026-10-07 联网读取 A2A 官方 README 和治理文档：其公开交付包含协议规范与文档站、多语言 SDK、示例、贡献渠道和版本治理。项目由 Google 贡献至 Linux Foundation，技术方向由 TSC 负责，官方仓库声明 Apache-2.0。重大技术和治理讨论以 GitHub 为记录来源，不以聊天群为唯一依据。

这种模式允许任何人依照规范独立实现通信双方；安装官方 SDK 是便利，不是符合协议的必要条件。G2A 应借鉴交付方式和互操作验证，而不是复制全部组织结构或把 Mot 内部接口更名为开放协议。

- 官方仓库与 SDK 入口：https://github.com/a2aproject/A2A
- 规范站：https://a2a-protocol.org/latest/specification/
- 治理：https://github.com/a2aproject/A2A/blob/main/GOVERNANCE.md
- 贡献：https://github.com/a2aproject/A2A/blob/main/CONTRIBUTING.md

## 对外应提供什么

| 交付物 | 作用 | G2A 当前边界 |
| --- | --- | --- |
| 版本化规范 | 规定角色、操作、状态、权限、错误和兼容性 | 0.1.0-dev 实验草案 |
| 机器可读定义 | 帮助独立实现验证消息 | 单一权威 JSON Schema，JS 副本自动检查 |
| 参考实现和 SDK | 降低游戏方和 Agent 方接入成本 | Python 宿主/客户端、Node 客户端；未公开包发布 |
| 两端示例 | 展示授权加入、观察、主动交流、行动、退出 | 确定性 HTTP 示例；缺少真实引擎示例 |
| 一致性测试 | 证明具体版本的可测要求 | 仓库测试不是第三方认证体系 |
| 文档站与版本下载 | 稳定可引用的入口 | 当前 GitHub 文档，网站待部署 |
| 贡献、安全与治理规则 | 让外部参与者知道如何改变协议 | 已有贡献/安全说明；长期治理待完善 |

## 建议发布顺序

1. **公开实验草案**：以独立 G2A 仓库为权威入口，发布明确标注 Experimental 的规范、示例和已知限制。现有 README 与 docs 可以先供评审，不必等基金会或标准组织批准。
2. **做一次真实游戏接入**：优先 Godot 游戏加独立 Agent。证明不依赖 Mot 也能加入、读观察、主动发言、执行游戏许可的动作并退出。不得以聊天演示代替动作授权和失败路径。
3. **补齐网站和版本发布**：可使用 GitHub Pages 或静态站点。规范版本和 SDK 版本分别记录兼容矩阵；固定版本文档与 latest 分开，历史版本不覆盖。域名、站点设置和公共包发布另行确认后执行。
4. **邀请外部试接入**：先邀请少量游戏和 Agent 开发者，仅凭公开文档独立实现；记录互操作问题。自己维护的 Python/JS 两种实现不能冒充两个独立厂商采纳。
5. **稳定后再发布 1.0**：处理破坏性变更、弃用期限、安全问题和兼容性测试。1.0 是稳定契约承诺，不是功能越多越好。

起步不需要建立大型委员会。先公开维护者、提案审查方式、破坏性变更规则、版本决策依据即可；以后有独立参与方，再共同确定治理结构。

## 发布前必须处理的边界

- 保留当前 LGPL 文件与权利来源。A2A 使用 Apache-2.0 不意味着 G2A 可以自动换证；应分别审视规范、SDK、示例和继承代码的权利，再由权利人决定。
- G2A 名称、域名、包名和商标可用性尚未确认；工作名不等于获得品牌权利，未核实前不宣称名称唯一。
- 不把公网部署实验 HTTP 宿主当作云端实现；生产身份、TLS、授权、撤销、资源限制及运维仍需实现和验证。
- 规范规定交换与授权语义，不强制某个记忆数据库、LLM、账号商或中心目录。渲染由游戏引擎执行，G2A 协商形象与呈现、传递事件和动作，不承担每帧图形渲染。
- 对外公告应明确版本、可运行范围、安装方法、示例、反馈入口、已知限制与安全报告路径。公开草案不应自称被行业认可的标准。

建议首条公告定位：**G2A 是一个面向游戏与玩家 AI 伙伴的独立开放协议实验草案，现邀请游戏及 Agent 开发者评审和试接入。** 不宣称任何游戏已普遍支持，也不承诺现有协议格式永久兼容。
