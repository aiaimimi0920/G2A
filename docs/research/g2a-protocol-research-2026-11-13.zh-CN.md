# G2A 外部协议与游戏 Agent 研究：r48 差距和采纳报告

研究日期：2026-11-13。对照基线：`796778b8af2ff8c0c4a54a7434b4c6b5a74ad8ae` 中的 `standard-review-2026-11-13-r48`。

本报告是研究与实施依据，不是新的规范版本，也不证明 SDK 已符合 r48。以下明确区分外部来源事实、现有 G2A 规定、建议和验收条件。来源优先采用官方规范、作者论文；`latest` 页面为本次访问快照，后续冻结版本时应保存精确版本或提交标识。

## 1. 结论

G2A 的产品方向已相当清楚，不应为了模仿其他协议而推翻玩家控制、游戏权威、开放接入和记忆迁移原则。主要差距是：新增文字规则与旧机器契约尚未完全统一，部分要求尚缺可运行的跨实现验收。

本轮所读资料没有同时覆盖 G2A 的全部目标，但不能据此断言全网不存在类似标准。游戏训练接口、通用 Agent 协议与游戏长期伙伴产品不是同一类别，不能仅凭名称或演示比较优劣。

建议先做：**唯一契约来源 → 动态可执行动作 → 动作结果/恢复测试 → 时间与多人调度语义 → 记忆和高级多模态细化**。技术精确化一般不需要再次盘问玩家；改变产品边界时才请求决定。

## 2. 保持不变的产品决定

- 基础 Agent 必须处理结构化游戏信息；图像和声音属于高级能力，不以纯视觉路线替换基础门槛。
- 符合最低标准的独立服务商可接入；身份验证、玩家授权和游戏能力检查仍各自成立。
- 玩家全局自主等级跨游戏保持，开发者建议不能静默覆盖；不绕过游戏权限或独立确认设置。
- 游戏控制实际玩法和效果，包括是否允许伙伴对战。玩家偏好不能创造未提供的能力。
- 玩家退出后不继续游戏活动，重新入场不自动复活旧任务。服务暂时不可用不阻止普通游戏。
- 动作有可查询编号及持久结果；未知不等于失败，查询无结果默认不重发。后续新动作须依据当前状态重新决定。
- 已发出的技能遵守游戏规则，取消请求不等于成功撤回。
- 当前保有的记忆和可表达设置可以迁移，不保证不同模型人格表现一致，不恢复已删除原始记录。
- 平台货币、充值、支付核对、分成和提现属于独立商业系统，不加入公开 G2A 核心。

## 3. 逐项对照与采纳建议

### R01 / P0：唯一权威的机器契约

**外部事实：**A2A 将数据模型、抽象操作和传输绑定分层，并声明数据定义的规范来源。[A2A §1.3–1.4](https://a2a-protocol.org/latest/specification/)

**G2A 已覆盖：**r48 §1、§5、§11、§19 已区分语义稿、继承的 `g2a-design-1` 契约和候选绑定；已有 `docs/protocol/contracts.py`、`contracts.schema.json`、`operations.json`，不能说当前毫无机器规范。

**缺口与建议：**每个对象、操作、错误和扩展选定唯一来源，生成派生 schema/字段表并检查漂移。发行清单记录语义稿、结构、操作、绑定及测试向量的版本与摘要。先选一个最小互操作绑定，不急着同时冻结全部运输方式；无需为模仿 A2A 强制换成 Protobuf。

**验收：**生成物与源一致；任何人工改动生成物或未更新摘要使检查失败；本次候选 profile 不冒充稳定版本。

### R02 / P0：静态能力与当前合法动作分离

**外部事实：**OpenSpiel 提供合法动作和玩家视角观察；Unity ML-Agents 提供离散动作屏蔽。[OpenSpiel API](https://openspiel.readthedocs.io/en/latest/api_reference.html)、[Unity 动作屏蔽](https://unity-technologies.github.io/ml-agents/Learning-Environment-Design-Agents/#masking-discrete-actions)

**G2A 已覆盖：**§8、§10 已要求能力、前置条件、观察新鲜度和执行边界验证。

**缺口与建议：**明确区分“游戏支持此能力”和“该角色此刻可执行此动作”。描述能力引用、当前可用性、相关观察版本、目标约束和失效条件；具体字段通过候选 profile 冻结。连续动作采用约束，不强制枚举无限动作。动态列表是决策信息，不是授权。

**验收：**旧状态、失效目标、资源不足、未知能力均有确定结果；错误和可用性信息不得泄露隐藏目标；效果提交前仍核验当前权限。

### R03 / P0：动作状态与恢复成为可运行轨迹

**外部事实：**MCP Tasks 定义可查询任务生命周期、保留期和结果获取，目前仍明确标为实验性。[MCP Tasks](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks)

**G2A 已覆盖：**§10.7、§12、§12.1 已要求动作编号、可查询持久结果、默认不重发、条件性撤回；核心既有状态/效果矩阵应继续保留。

**缺口与建议：**将文字状态对应到唯一机器状态/效果表。不要再创造一组与既有矩阵竞争的同名枚举。覆盖：接收未执行、执行中、成功、失败含部分效果、结果未知、记录过期、取消来迟。编号格式与日志保管方不必统一，但标识作用域、关联语义、权限和保留边界必须明确。

**验收：**断线恢复先查原编号；未知、丢失、过期都不触发自动重发；同编号不同内容不能混为同一动作。仅平台接收日志不能证明游戏执行效果，去重不能被宣称为无限期恰好一次。

### R04 / P0：公开测试不止一张要求清单

**外部事实：**PettingZoo 提供可由环境作者运行的 API、并行接口等测试。[PettingZoo 测试工具](https://pettingzoo.farama.org/content/environment_tests/)

**G2A 已覆盖：**§18 有较详细的符合性场景；仓库已有多个 harness 和跨语言 peer，应复用、审计覆盖范围，而非重新从零建立平行测试体系。

**缺口与建议：**为新增规则提供固定输入、预期输出、反例和可运行入口。区分结构校验、SDK 单元测试、同实现回环、独立客户端互通和真实游戏验收。

**验收：**至少涵盖隐藏信息隔离、旧观察、目标失效、未知动作不重发、取消竞态、退出后不恢复任务、跨服务商同等准入。不能以旧测试总数证明新 r48 规则已验证。

### R05 / P1：决策时钟与多人提交规则

**外部事实：**Unity 支持按时机请求决策；PettingZoo 分别提供顺序行动和并行行动接口。[Unity Decisions](https://unity-technologies.github.io/ml-agents/Learning-Environment-Design-Agents/#decisions)、[PettingZoo Parallel](https://pettingzoo.farama.org/api/parallel/)

**G2A 已覆盖：**§8.4、§10.2、§13 已有新鲜度、资源和时间原则。

**缺口与建议：**另行定义实时/回合制模式、观察对应状态、行动窗口、持续时间、截止时间和错过窗口的行为。自主等级表示决策自由度，不应机械等同模型调用频率；游戏物理控制也不等于模型规划频率。多人同回合结算顺序由游戏表达，客户端不能默认网络先到先得。

**验收：**过期动作不被静默当作当前动作；多人同时提交遵守声明规则；高自主可事件触发而非每帧推理。不要把实时游戏强制改成等待模型的同步 step 循环。

### R06 / P1：终止原因与任务结果分开

**外部事实：**Gymnasium 区分任务意义上的终止与外部截断。[Gymnasium 时间限制](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)

**G2A 已覆盖：**§7、§10.4、§12 已区分游戏状态、服务失联和授权边界。

**缺口与建议：**给任务完成、失败、角色死亡、玩家撤回、离开游戏、断线、预算停止和超时建立映射，不混成一个失败码。普通角色死亡不删除跨游戏身份或记忆。

**验收：**Agent 连接中断不能直接产生“Boss 已击败/任务失败”的事实；会话恢复不能自动启动旧目标。

### R07 / P1：能力目录与错误都应可供机器解释

**外部事实：**MCP 工具有输入/输出结构、目录变化通知和工具执行错误；RFC 9457 将机器问题类型与具体说明区分。[MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html#section-3)

**G2A 已覆盖：**§6、§11、§13 已有能力替换、错误分类和拒绝原因要求。

**缺口与建议：**冻结参数/结果 schema、目录 revision、旧请求失效规则、错误代码与安全解释。运输失败与游戏效果失败分开；不要让客户端解析中文/英文说明判断是否可重试。能力更新不能自动扩大玩家 grant。

**验收：**代码和说明一致、未知扩展处理确定、拒绝原因不泄露隐藏状态。不要照搬成每次动作都弹确认，保持用户已选自主策略。

### R08 / P1：开放生态不等于无身份边界

**外部事实：**MCP HTTP 授权要求面向资源的令牌验证，不把上游令牌当成下游万能凭据。[MCP Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)

**G2A 已覆盖：**§2、§3、§7、§14、§16 已分离身份、同等准入、玩家授权与游戏执行。

**缺口与建议：**把主体、目标资源、有效期、作用域和 challenge 规则落实到生产 profile。单机可有更简单的身份通道，不必强制 OAuth，但不能把测试 enrollment 称为生产安全。

**验收：**相同协议能力的服务商准入一致；A 游戏凭据不能访问 B 游戏；知道动作编号不等于有权查结果。

### R09 / P1：事件信封与动作标识各司其职

**外部事实：**CloudEvents 1.0.2 以来源和事件 ID 共同识别事件，定义通用事件上下文。[CloudEvents 1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md)

**G2A 已覆盖：**§8、§10.7、§12 已有接收者可见事件、目标变化和动作编号。

**缺口与建议：**固定事件类型、来源、事件 ID、schema 引用及关联动作字段；不要把 Boss 死亡事件的 ID 当作此前攻击动作的 ID。沿用接收者可见游标，不以全局连续编号泄露其他玩家事件。

**验收：**重复事件可识别，事件去重不被声称为动作恰好一次；恢复仅当前快照及必要动作结果，不偷偷增加断线经历回放。

### R10 / P1：记忆迁移保留认识来源

**外部事实：**Generative Agents 区分观察、反思与计划，反思可引用来源，论文也报告记忆添枝加叶的问题。[原论文 §4、§6](https://arxiv.org/html/2304.03442v2)

**G2A 已覆盖：**§9 和记忆迁移候选稿已有来源、编辑、删除及导出要求。

**缺口与建议：**冻结记录类型、游戏/周目、观察时间、修改时间、推断依据、来源被删除标记。导入总结不应升级成游戏权威事实，计划不等于已发生经历。仅迁移当前保有的记录及可表达设置，不保证模型人格完全复现。

**验收：**两个导入器能解释同一包；不支持字段明确返回，不默默丢失；删除的原始记录不能从摘要或过期索引中冒充恢复。保留玩家对建议的覆盖权，不另加开发者跨游戏禁令。

### R11 / P2：多步骤技能和多模态分层

**外部事实：**Voyager 使用技能库和反馈修正；SIMA 2 研究基于画面与键鼠的跨虚拟环境行动，属于 Agent 研究而非开放协议。[Voyager](https://arxiv.org/html/2305.16291v2)、[SIMA 2](https://arxiv.org/html/2512.04797v1)

**G2A 建议：**可选复合技能声明依赖、参数、子动作和部分效果；多模态 profile 对齐画面、声音和动作时间。服务商可内部采用快执行/慢规划，不等于游戏同时存在多个伙伴。模型自检是规划证据，不是游戏效果凭证。

**不照搬：**不把任意生成代码远程执行作为基础能力；不强制训练奖励函数；不以纯视觉路线替换结构化最低门槛；不因论文持续探索而允许玩家离线后继续活动。

## 4. 实施落点与验收门槛

| 批次 | 建议落点 | 完成证据 |
| --- | --- | --- |
| A | 现有机器契约与 schema 生成工具；规范发布清单 | 生成检查、漂移反例、候选版本明确 |
| B | 动态能力候选 profile 与 SDK 校验入口 | 当前状态/失效目标/无权限向量通过 |
| C | 现有动作 harness 和公开测试入口 | 未知不重发、取消竞态、部分效果和权限测试 |
| D | 时间、多人调度和记忆 profile | 字段冻结、独立实现交叉验证 |

具体文件名和字段由实施时的真实仓库决定，不将本报告的描述性例子直接当成已发布 wire 字段。候选方案应先与继承契约对齐，再更新语义稿。

### 4.1 融合到正文，而非逐轮叠加条款

下表定位的是 **r48 基线章节**，不是要求新增同名附录。实施应直接重构中英文对应正文：一个概念只设一个权威定义，其他章节引用它；保留历史研究与修订记录作为证据，不让历史结论继续构成并行规范。

| 研究项 | r48 具体融合/替换位置 | 重构方式 |
| --- | --- | --- |
| R01 | §1 文档效力、§5 数据模型、§11 操作目录、§19 实现边界 | 将散落的契约来源说明收敛为唯一来源与派生关系；操作表引用同一版本清单，不再追加第二套实体定义。 |
| R02 | §8 观察、§10 行动 | 在观察内定义当前动作可用性视图，在行动内定义提交时验证；发现目录仅保留静态能力，不把两者重复成两套能力列表。 |
| R03、R06 | §10 行动与效果、§12 恢复 | 把动作状态、终止原因及取消边界融合为一张状态关系；恢复章节仅规定查询与重连处理，删除与状态定义冲突的重复措辞。 |
| R04 | §18 符合性与验收 | 用要求 ID、测试向量和证据层级组织现有验收内容，不在每轮末尾追加“新增测试规则”。 |
| R05 | §13 时间与限制，关联 §8、§10 | 集中定义时钟、状态新鲜度和决策窗口；观察与行动引用它，不将自主程度误写成统一采样频率。 |
| R07、R08 | §6 协商准入、§7 授权、§13 错误、§16 安全 | 区分准入资格、会话权限、当前动作合法性；错误结构只定义一次，安全章节解释威胁而不另创冲突策略。 |
| R09 | §5 数据模型、§8 事件、§12 投递 | 集中定义事件和动作的不同身份；事件重投与动作重执行分开表述。 |
| R10 | §9 记忆与私人数据、既有 memory-portability 候选稿 | 主规范定义语义和玩家权利，候选稿承载格式；删去或改成引用重复字段说明，避免两个版本自行演化。 |
| R11 | §15 可选配置规范与扩展 | 保留为可选高级能力，不扩大基础准入要求；未冻结的研究方向只留在研究报告。 |

重构验收除测试外，还应检查：同一术语是否只有一个定义、双语章节是否一致、旧条款是否仍给出相反结论、例子是否使用当前契约。新增内容不得削弱已确认的“未知结果默认不重发”等产品决定。本报告只提出融合路径，不直接修改规范或实现文件。
## 5. 验证状态与维护方法

- 本报告核对 r48 本地文档及原始资料，不宣称已完成全部 SDK/互通测试。
- 保留 [既有 2026-10 协议研究](../protocol/PROTOCOL_RESEARCH.md) 的历史证据；本篇是 r48 产品决定后的增量对照，不覆盖旧验证结果。
- 实施记录应给每个 R 编号标注“未实施 / 候选实现 / 测试通过 / 独立互通通过”，附具体提交与测试输出，不凭计划修改为完成。
- 每次规范更新只修订受影响的对照行，避免累积大量重复阶段报告。
- 涉及产品边界的新冲突再请用户决定；纯字段、验证和兼容设计由工程实现负责，不重复询问已确认场景。


## 6. 串行整合验证台账

### 第 1 轮：r48 → r49

- 采用：统一权威定义、动态合法动作、决策与执行节奏、事件身份、来源化记忆、机器错误及查询恢复；融入既有 §1、8、9、10、12、13、18、21，精简 §12.1 重复条款。
- 保留边界：未知默认不重发、玩家偏好不扩大游戏授权、不要求每帧模型推理、不以论文能力替代基础准入。
- 文档验证：中英 54 个编号标题一致，围栏配对、UTF-8 与相对链接检查通过，git diff --check 通过。未执行生产互通或 SDK 验收。

### 第 2 轮：r49 → r50，认证、委托与资源边界

- 来源：[RFC 9700 §2.3](https://www.rfc-editor.org/rfc/rfc9700.html) 的最小权限与资源/动作限制；[RFC 8693 §1.1](https://www.rfc-editor.org/rfc/rfc8693.html) 的 actor/subject 区分；[MCP 安全实践 2025-11-25](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices) 的令牌透传、SSRF 与会话劫持风险。原文由本轮研究者读取后再整合。
- 采用：在既有 §3、7、14 合并主体/调用方/委托区分、每次资源受众校验、查询授权、下游凭据约束、URL/重定向/DNS 重绑定检查；在 §18 补对应拒绝及合法本地访问向量。
- 不采用：不强制 OAuth 或中心平台；不建立服务商白名单；不一律禁止局域网目标；这些仍是 G2A 自身的抽象约束，不声称兼容上述协议的线上消息格式。
- 验证：中英编号标题一致、修订号 r50、围栏配对、无替换乱码、相对链接存在；git diff --check 通过。未改 SDK、运行时或机器契约；未提交、未发布；未将文档向量要求表述为已通过实现测试。

### 第 3 轮：r50 → r51，Schema、规范化与兼容维护

- 来源：[JSON Schema 2020-12 core §8.1.2](https://json-schema.org/draft/2020-12/json-schema-core) 的必需词汇处理；[RFC 8785 §3.2.3](https://www.rfc-editor.org/rfc/rfc8785.html) 的 UTF-16 键排序；[RFC 9413 §5.1](https://www.rfc-editor.org/rfc/rfc9413.html) 的明确异常处理与协议维护。研究者在第 2 轮整合完成后读取原文，再开始本轮。
- 采用：修订既有 §1、14、15、17、18，固定 Schema 方言/词汇/离线依赖，区分 Schema 与语义验收；明确未知枚举及协商失败策略；分类兼容变更并约束临时例外。
- 不采用：不将 g2a-cjson-1 替换为 JCS，明确两者标量值/UTF-16 排序差异；不将未知关键词被解析等同约束已验证；不靠静默降级或宽松解析取得兼容。
- 验证：中英编号标题、r51、围栏、UTF-8、相对链接通过；git diff --check 通过。新增的是公开验收向量要求，并非已执行跨 SDK 互通测试；未改代码、未提交发布。

### 第 4 轮：r51 → r52，时钟、状态合并与背压

- 来源：[RFC 7641 §3.3–3.4](https://www.rfc-editor.org/rfc/rfc7641.html) 的观察中间态省略、新鲜度及重排；[W3C High Resolution Time 2026-11-06 Working Draft](https://www.w3.org/TR/2026/WD-hr-time-3-20261106/) 的本地单调时钟与墙钟区别。后者是工作草案，不标为正式 Recommendation。研究者在 r51 完成后读源；ROS QoS 网页访问遭拒，不列为已读或采用依据。
- 采用：合并进既有 §8.3/8.4/13/18，区分可合并状态样本与不得静默丢弃的动作回执/撤权/撤回，明确溢出重同步、时钟域及纪元、接收时间与生成时间、背压独立于自主等级。§10.2 已有频率区分，未重复追加。
- 不采用：不强制 CoAP、WebSocket、特定频率或断线全过程回放；不假定单调时钟天然跨机器同步。
- 验证：中英标题、r52、围栏、UTF-8、相对链接及 git diff --check 通过。只更新规范和研究台账，没有运行时或 SDK 更改，也未声称实时集成实测通过。

### 第 5 轮：r52 → r53，记忆来源、迁移损失与可测断言

- 来源：[W3C PROV-DM §5.2.2](https://www.w3.org/TR/prov-dm/) 的派生/修订关系；[ActivityStreams 2.0 §5.2](https://www.w3.org/TR/activitystreams-core/) 的扩展再序列化信息损失；[W3C QA Framework Specification Guidelines §2.1](https://www.w3.org/TR/qaframe-spec/) 的符合性类别与可测断言。研究者在 r52 验证后读取原文。误开的 RFC 8499 不相关，未引用或采用。
- 采用：修订既有 §9.7 来源与迁移清单，明确玩家修订/模型派生、来源删除标记、选定范围与转换损失、安全扩展保留但不执行、凭据不进入导出；§18合并条款—角色—前置条件—输入—允许/禁止结果—证据与不适用理由的断言映射。
- 不采用：不要求 RDF、JSON-LD、完整 PROV 或永久原始记忆；不保证模型性格一致；不将文本断言当成已实现测试集。
- 验证：54 个中英编号标题一致，r53、围栏、UTF-8、相对链接、git diff --check 均通过。核心原则哨兵检查覆盖未知不重发、玩家偏好优先、游戏权限、开放准入、每玩家一个伙伴、可留空、收起停止观察、重连不自动恢复、记忆迁移与性格差异；未改变平台商业体系与公共协议分离。
